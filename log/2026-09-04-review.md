# Structure and implementation review

Last checked: 2026-07-29

## Current structure

- `src/fypp/`: generation source for the Serial/Parallel API
- `src/serial/`, `src/parallel/`: build-target Fortran generated by fypp
- `src/h5fort.F90`: facade for the public Serial/Parallel API
- `test/`: tests for Serial, Parallel, Visualization HDF5, and install consumer
- `example/`: independent usage examples for the Serial/Parallel procedural and OOP API and visualization output
- `docs/`: API, visualization schema, postprocessing, tests, TODO

Synchronization between generation sources and generated files is checked with:

```sh
src/fypp/generate_fypp.sh
src/fypp/generate_fypp.sh --check
```

## Current design decisions

### Fortran and Python responsibilities

The Fortran solver outputs 1 `seqNNNNNN.h5` per 1 output step. The snapshot
HDF5 is authoritative for field values and metadata.

Python scans snapshot files with metadata-only access and builds the regenerable index `metadata.h5`.
UNLIMITED append from the solver to a central manifest was not adopted.

Reasons:

- Keep the solver's critical path simple
- Avoid inconsistencies from writing both snapshot and manifest
- Remove the need to implement expansion of central HDF5 from MPI at every step
- Allow recovery of the manifest from snapshot files

### XDMF

XDMF/XML generation in Fortran was removed. Python reads `metadata.h5` and generates
time-series XDMF for each mesh group name. The standard configuration separates fluid and soil particles.

```text
fluid.xdmf
soil_particles.xdmf
```

XDMF holds no field payload; it references snapshot HDF5 as Heavy Data.

### Mesh

Meshes with connectivity and a fixed node count per 1 element are handled generically using `topology_type` and
`nodes_per_element`.

Verified:

- Hexahedron
- Tetrahedron
- Quadrilateral
- Triangle
- Polyvertex

XDMF `Mixed` topology is unsupported.

### Time-series variability

For a given mesh name, topology, nodes per element, field composition, dtype, and centering remain
fixed throughout the time series. node count, element count, particle count, and time may vary by step.

Each dataset within a snapshot is fixed-size; changes in entity count are handled by writing
a separate file at each step. The general-purpose Fortran UNLIMITED append API is not used for visualization
metadata.

### node entries at MPI boundaries

Each rank outputs its owned cell and all local node entries they reference. Shared and halo node entries may be
duplicated for each rank, and connectivity is passed to the writer as rank-local 0-origin ID.
The writer adds the global output offset, so no prior communication to unify node numbering is needed.
ghost cell entries are not output. To merge duplicate node entries, use ParaView's `Clean to Grid`.
A halo exchange is performed before output only when field values on shared node entries need to
agree.

## Verified

- Serial/Parallel source generation and synchronization check with fypp 3.2
- clean CMake configure/build
- Serial-only build
- Intel MPI Fortran + Parallel HDF5 build
- Serial read/write, attributes, error contract
- Parallel read/write, a rank with 0 elements, shape/rank checks, OOP API
- 2-rank Visualization HDF5 output
- Multiple mesh group entries and generalized topology
- Creation and incremental update of the Python manifest
- Python XDMF generation and CLI
- Empty Spatial Collection representation for time series containing a step with 0 particles
- External consumer build after install
- end-to-end example from Fortran snapshot to XDMF
