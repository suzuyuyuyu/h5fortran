# v1 patch変更履歴

## v1.0.1: 空粒子時系列のParaView互換性修正

### 問題

Polyvertexの粒子数が0のとき、従来のXDMFはGeometryとPoint Attributeについて
`Dimensions="0 ..."`のHDF5 DataItemを各stepに出力していた。ParaViewでは最初の
周回を表示できるものの、最終stepから先頭stepへ戻る際にプロセスがクラッシュした。
Point Arraysを無効にしても再現したため、空のGeometryを含むtemporal Gridの更新が
原因と判断した。

### 検証

最小HDF5/XDMFを用いて、次の空step表現をParaViewで比較した。

- ゼロサイズHDF5 DataItem: `1 -> 0 -> 1`を表現できるが2周目でクラッシュ
- XDMF内の未使用ダミー点: クラッシュしないが粒子数0を正しく表現できない
- HDF5内の未使用ダミー点: クラッシュしないが粒子数とfield表示が不正確
- 空Spatial Collection: `1 -> 0 -> 1`を正しく表現し、10周以上クラッシュしない

### 変更

- 空stepを含むmeshだけ、XDMFの各stepをSpatial Collectionで包む。
- 非空stepには従来のUniform Gridを1個置く。
- 空stepは子Gridを持たないSpatial Collectionとし、HDF5 DataItemを参照しない。
- HDF5 snapshotと`metadata.h5`のentity数、field、schemaは変更しない。
- `1 -> 0 -> 1`と全step 0の回帰テストを追加する。
- `h5fortran`と`h5xdmf`の製品バージョンを`1.0.1`へ統一する。
- `h5xdmf/_version.py`を製品バージョンの正本とし、CMakeとPython packageが同じ
  値を参照する構成へ変更する。
- HDF5の`scheme_version`を製品majorと常に一致させる。CMakeは
  `h5fort_version` moduleを生成し、製品版とscheme版をFortran writerおよび利用者へ
  公開する。Pythonは製品majorに対応するschemeが登録されていることを起動時と
  テストで検査する。

### 互換性

全stepが非空のmeshは従来のUniform Grid時系列を維持する。空stepを含むmeshは
ParaView上でcomposite datasetとして読まれるため、Point Gaussianなど表示設定の
自動スケーリングがstepごとに変化する場合がある。これはparticle countやHDF5値の
変化ではなく表示側の設定であり、必要ならGaussian Radiusを固定する。
