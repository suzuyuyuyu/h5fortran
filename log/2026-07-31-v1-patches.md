# v1 patch history

## v1.0.1: ParaView compatibility fix for empty particle time series

### Problem

When the Polyvertex particle count was 0, the previous XDMF output HDF5 DataItem entries with
`Dimensions="0 ..."` for Geometry and Point Attribute at each step. ParaView could display the first
cycle, but the process crashed when returning from the last step to the first step.
The issue reproduced even with Point Arrays disabled, so updating the temporal Grid containing
empty Geometry was judged to be the cause.

### Verification

The following empty step representations were compared in ParaView using minimal HDF5/XDMF.

- Zero-sized HDF5 DataItem: represented `1 -> 0 -> 1`, but crashed on cycle 2
- Unused dummy point in XDMF: no crash, but could not correctly represent a particle count of 0
- Unused dummy point in HDF5: no crash, but particle count and field display were inaccurate
- Empty Spatial Collection: correctly represented `1 -> 0 -> 1`, with no crash for 10 or more cycles

### Changes

- Wrap each XDMF step in a Spatial Collection only for a mesh containing an empty step.
- Place 1 existing Uniform Grid in each nonempty step.
- Represent an empty step as a Spatial Collection with no child Grid, without referencing HDF5 DataItem entries.
- Leave entity counts, field, and schema in the HDF5 snapshot and `metadata.h5` unchanged.
- Add regression tests for `1 -> 0 -> 1` and every step at 0.
- Align the `h5fortran` and `h5xdmf` product versions at `1.0.1`.
- Make `h5xdmf/_version.py` the authoritative product version, with CMake and Python package referencing the same
  value.
- Keep HDF5 `scheme_version` always equal to the product major. CMake generates the
  `h5fort_version` module and exposes the product version and scheme version to the Fortran writer and users.
  Python checks at startup and in tests that a scheme corresponding to the product major
  is registered.

### Compatibility

A mesh with every step nonempty retains the existing Uniform Grid time series. A mesh containing an empty step is
read as composite dataset in ParaView, so automatic scaling of display settings such as Point Gaussian
may change from step to step. This is a display setting, not a change in particle count or HDF5 values;
fix Gaussian Radius if needed.
